# Phase 19: Linux verification

Make the Bubblewrap backend verifiable on a real Linux host. Add `scripts/verify-linux.sh` that checks prerequisites (bwrap present, unprivileged user namespaces allowed), runs `WYRIT_REQUIRE_NATIVE_SANDBOX=1 python3 -m unittest discover -s tests`, and prints a summary of the containment probes. Add a GitHub Actions workflow (`.github/workflows/linux-sandbox.yml`, manual trigger plus pull requests touching `src/wyrit/native_sandbox.py`) that runs it on an Ubuntu runner, with read-only permissions and no secrets.

Fix what the Linux probes reveal within the security model: no widening of the sandbox to make a probe pass. If a guarantee cannot be enforced on a host, the backend refuses to run there (fail closed) and says why. Update the guarantees in `docs/HANDOFF_PHASE_19.md`: either Linux is verified with the evidence, or the remaining gap is listed probe by probe and Linux stays refused.

The gate runs on macOS inside a sandbox and cannot run Bubblewrap, so tests here cover the script's prerequisite checks and the backend's fail-closed refusals with mocks. Produce the phase handoff with the operator steps.

**Inside a container (added 2026-11-23).** The first embedder runs in Docker on Linux, so verify there too. Add `examples/container/Dockerfile` (a `python:3.12-slim` image with Node.js, bubblewrap and Wyrit installed, running as a non-root user) and `scripts/verify-linux-container.sh`, which builds it and runs the native suite inside the container under Docker's default security settings first, then reports exactly which setting blocks the sandbox if it fails (seccomp profile, AppArmor, user namespaces). Document the least-privilege settings that make it work, if any, in the handoff, with what each one exposes. Never recommend `--privileged`, `CAP_SYS_ADMIN` for the container, or disabling seccomp entirely. If no acceptable setting works, the backend refuses inside the container with a clear reason, and the handoff says what an embedder's alternatives are.
