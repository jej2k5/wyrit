# Phase 13: Console, monitoring and dashboard

Extend the phase 12 console with what agents are doing, read only from the phase 10 run ledger and the phase 9 health records. Never derive state the host does not record. Same security and design rules as phase 12.

- **Health strip:** servers connected, capabilities exposed, runs in the last hour, and what needs attention (a server down, failures or denials above the recent norm).
- **Live run feed:** runs as they happen, newest first, append-only and pausable: each action in order with outcome glyph and word (SUCCEEDED, FAILED, DENIED, UNKNOWN), duration and size. UNKNOWN is called out with a note that the downstream system may need checking.
- **Per-capability view:** calls, success, failure, denial and unknown rates, and p50/p95 latency over a chosen window (last hour, day, week).
- **Per-server view:** connection history, reconnects and calls lost to drops.
- **Budgets and policy:** which limits runs hit and which writes were denied.
- **Capture, off by default:** an operator may turn on argument and result capture per server with a retention limit; the console shows clearly when capture is on and purges expired entries. Generated code is captured only under the same switch.
Every number links to, or can be traced to, the ledger lines behind it. Polling is cheap: read the ledger incrementally rather than rereading it whole.

Tests (offline): from a synthetic ledger and health history, each view's numbers match a hand computation; percentiles are correct; capture stays off by default and purges on schedule; the feed survives a ledger file rotation. Produce the phase handoff.

**Phase 13 review, attempt 1 (operator, 2026-11-23):** the operator reviewed attempt 1 with 21 real runs in the ledger. The numbers were correct; the page was not usable as a dashboard. Rework the Monitoring page:
1. **Show what was run.** The operator's first complaint: a run shows which capabilities were called but not the code the agent executed. Change the capture default: store each run's generated JavaScript source by default, with a default retention of 7 days (configurable, and switchable off per server). The existing credential suppression still applies: if the source contains a resolved credential or a credential-shaped string, store nothing and show "source withheld: looked like a credential". Arguments and results stay off by default, opt-in per server as before. The console must say plainly what is stored (code on, arguments and results off) and for how long. Update the handoff and any doc that states the old default.
2. **Summary first.** Order the page: health strip with "needs attention" first, then capability activity, limits hit and writes denied, server history, then the run feed. Nothing an operator scans for should sit below the feed.
3. **Needs attention must fire.** With the attempt 1 ledger (3 runs hit `run_deadline`, 2 writes denied, failed runs), the strip must flag them. When there is no 23-hour baseline, flag any failure, denial, limit hit or UNKNOWN in the window rather than staying silent. Remove the duplicated "Ledger sources" items from the strip.
4. **Compact, scannable feed.** One row per run, collapsed by default: time, outcome as a coloured glyph plus word (SUCCESS, FAILED, TIMED_OUT, ...), the capability sequence as short names, duration, and the first line of the source. Expanding a row shows the full source (monospace, preserving whitespace), the per-call table, the run's failure reason (e.g. "Run deadline exceeded", "JavaScript execution or serialization failed", or the first DENIED call), and the ledger link. Show a short run ID (first 8 characters) with the full ID available on expand.
5. **Fix small defects:** reconnect and lost-call cells showing "0—"; capability names breaking mid-word (allow wrapping only at `.` or `_`, or widen the column).
Tests: the attempt 1 scenario (a synthetic ledger with successes, deadline hits, write denials and a failed run) produces attention items; source is stored by default and withheld when credential-shaped; arguments and results stay uncaptured by default; feed rows render collapsed with the first source line.
