# Phase 18: Embeddable host

Today Wyrit is an MCP proxy: one trusted host process, one set of downstream credentials from environment variables, the same catalog for every caller. Products that already own identity, authorization and audit, such as a multi-tenant data agent that runs every tool on behalf of the signed-in end user, cannot put Wyrit in front of their tools without flattening that model. This phase makes Wyrit embeddable: the host application brings its own capabilities, its own dispatch and the identity of each run, and Wyrit contributes the disposable runtime, the invocation protocol, budgets, outcome codes, recipes and the ledger records. The first intended embedder is a Python data agent whose `dispatch_tool` enforces tenant policy and on-behalf-of auth; keep the API generic and name no product.

**Public API** (`wyrit.embed`, documented in `docs/EMBEDDING.md`, stable names, type hints):
- `Capability` specs supplied by the host: ID, description, input schema, read or write class.
- `RunContext`: an immutable, host-defined identity for one run (principal, tenant and free-form attributes). It is passed to the host's callbacks and recorded by reference (a host-supplied context ID) in ledger records. It is never serialized into the guest: generated code cannot read it, and nothing derived from it appears in results or errors except what the host's own dispatch returns.
- `Host(capabilities | catalog_provider, dispatch, *, budgets=None, recipes=None, ledger_sink=None)`. `catalog_provider(context)` returns the capabilities visible to that run, so two principals can see different catalogs. `dispatch(capability_id, arguments, context)` is an async callable that performs the call in the host's trust domain and returns a JSON value, or raises `CapabilityError(code, reason)` with a code from the phase 15 set (a host policy refusal is `DENIED` with the host's reason). Any other exception from dispatch maps to `TOOL_ERROR` with no host text reaching the guest.
- `await host.execute(source, context)` and `await host.run_recipe(name, arguments, context)` return the same result shape as the MCP tools; `host.catalog_text(context)` renders the phase 15 catalog for that principal so the embedder can put it in its own tool description.
- `ledger_sink(record)` receives run and action records (with the context ID) so the embedder can write them to its own audit store; the default is the phase 10 JSONL ledger.

**Concurrency and isolation.** Many runs may execute at once, each in its own disposable sandbox, with per-run budgets. No state is shared between runs or principals beyond the host's catalog and recipes. Write policy, budgets and recipe rules apply inside embedded runs exactly as in the MCP server.

**One code path.** Refactor the existing MCP server to be a client of this API (its configured downstream sessions become a catalog provider and dispatch), so the proxy and embedders share one execution path and the existing tests prove the API is reachable.

**Example.** `examples/embed/`: a minimal host with two in-memory "SQL" capabilities whose dispatch checks a per-principal permission table, showing two users running the same script and getting different results and a `DENIED` for one of them.

Tests: two concurrent runs with different contexts get different catalogs and dispatch receives the right context each time; generated code cannot observe the context by any means (globals, errors or results); `CapabilityError` codes and reasons map through and other dispatch exceptions become `TOOL_ERROR` without leaking text; budgets, write policy and recipes apply in embedded runs; the ledger sink receives records with the context ID; the MCP server still passes its full suite through the new path; the example runs. Produce the phase handoff.

**Test secrets (operator note, 2026-11-23):** buildctl refuses any changed file containing a credential-shaped literal (`ghp_…`, `sk-…`, JWT-shaped strings, or `token = "<long literal>"`-style assignments), even a fake one, and fails the phase. Build fake secrets at runtime instead, for example `FAKE_TOKEN = "ghp_" + "x" * 36`, and never write the assembled value into a source, fixture or snapshot file.
