# Phase 14: The measurement harness

Build a benchmark that runs the same multi-step tasks two ways against the same downstream tools: an agent with direct MCP tool calls, and an agent with Wyrit's `search` and `execute`. It records, per run: model input and output tokens (from the API's usage fields), model turns, wall time, tool calls and whether the task's answer is correct (each task has a checker). Code lives under `bench/` with its own README; it calls the Anthropic Messages API with the model configurable and the API key read from `ANTHROPIC_API_KEY`, and it is never imported by the `wyrit` package.

Tasks (deterministic fake MCP servers for the first three, so results are reproducible):
1. Filter and join two tools' results, returning only mismatches.
2. A dependent chain: list, fetch details for matching items, aggregate.
3. A failing tool and a denied write; score whether each approach reports the outcomes correctly.
4. Real, read-only: on the `jej2k5/mcpxy-test` GitHub repository, list issues, read their comments and count those matching a condition (needs a token from the environment; skipped cleanly without one).
The operator may swap any task for one from their own work; tasks are data files, not code changes.

**Calibration first:** `python -m bench calibrate` runs each task once per approach, prints measured tokens and cost per run, and the projected cost of the full benchmark (tasks x approaches x repetitions, prices from a config table the operator can edit), then stops. `python -m bench run --repetitions N` runs the full benchmark only when given that projection's ID, so it cannot start by accident. It writes a report (Markdown and JSON) with per-task and overall numbers and variance, including where Wyrit loses.

The gate is offline, so tests use a fake model client and the fake servers: the harness wiring, token accounting, cost projection, checkers, the refusal to run without a calibration ID, and report generation. No test calls the real API. Produce the phase handoff with the exact operator commands.

**Claude Code driver (operator, 2026-11-23):** the operator has a Claude subscription, not API credits, so add a second agent driver that runs each task through Claude Code in headless mode, billed to that subscription. Keep the existing Messages API driver; the subscription driver becomes the default and the API driver is selected with `--driver api`.
- **Invocation, one Claude Code process per task run:** `claude -p "<task prompt>" --output-format stream-json --verbose --model <model> --tools "" --strict-mcp-config --mcp-config <generated json> --allowedTools "mcp__*" --permission-mode dontAsk --no-session-persistence --setting-sources "" --disable-slash-commands`, run in a fresh empty temporary directory, with the task's system instructions passed through `--append-system-prompt`. Never pass `--bare`: it accepts only `ANTHROPIC_API_KEY` and ignores the subscription login. Never read, copy or pass Claude Code's credentials yourself; the `claude` process uses its own login. `ANTHROPIC_API_KEY` must be removed from the child's environment so the subscription is used.
- **The two approaches:** *direct* gives Claude Code the task's downstream servers as stdio MCP servers in the generated config; *wyrit* gives it only Wyrit's MCP server (`python -m wyrit.mcp_server --config <generated wyrit.toml>`) with those same servers as Wyrit's downstreams. The in-memory fake servers therefore also need a stdio entry point (a small module that serves one named fixture over MCP stdio), used by both approaches so the tools and data are identical.
- **Metrics:** from the final `result` event take `num_turns`, `duration_ms`, `usage` (input, output, cache creation and cache read tokens, reported separately and as a total), `total_cost_usd` (label it "list-price equivalent; billed to the subscription"), `is_error` and `result` (the answer). Count tool calls from the `tool_use` blocks in the streamed assistant events. Correctness uses the same checker as the API driver.
- **Calibration and authorization stay:** calibrate runs each task once per approach and prints projected list-price cost, projected subscription usage (total tokens) and wall time for the full benchmark, then stops with an ID; `run` requires that ID. A run that hits a usage limit or exits non-zero is recorded as an error with the reason, not retried silently. Add a per-run timeout (default 600 s) and kill the process tree on expiry.
- **Report:** keep the API driver's report shape, add the driver name, and note that Claude Code's own fixed instructions are included equally in both approaches, so the comparison is the difference, not the absolute counts.
- **Tests stay offline:** a fake `claude` executable on `PATH` that emits recorded stream-json for both approaches; assert the exact argument list (including the absence of `--bare` and of `ANTHROPIC_API_KEY` in the child environment), metric extraction, tool-call counting, timeout handling and the error path. No test may launch the real `claude`.
- Update `bench/README.md` and the handoff: the default command needs only a signed-in Claude Code (`claude` on `PATH`); `GITHUB_TOKEN` stays optional for the GitHub task.
